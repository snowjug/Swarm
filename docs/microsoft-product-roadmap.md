# Microsoft product roadmap — Swarm Lab

Written from the gap analysis in [requirements-matrix.md](./requirements-matrix.md). Priorities mean:

- **P0** — required for a technically credible prototype
- **P1** — required for a strong internal Microsoft demo
- **P2** — required for production-grade architecture
- **P3** — advanced research / product opportunities

Nothing here connects a paid Azure resource. The deterministic local mode stays the default and stays
functional throughout. Status markers: ✅ done and evidenced · ⛔ blocked on something outside the
repository · ⬜ not started.

## P1 — strong internal demo

| Item                                                                                  | Why it matters                                                                                                                                           | Notes                                                                                                             |
| ------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Fluent-style design system with **light, dark and high-contrast themes**              | A product-review bar; today the console is a single light theme                                                                                          | Evaluate Fluent UI React v9 tokens and Segoe UI Variable; keep the existing CSS-variable layer as the seam        |
| **Per-actor model reasoning** with shared memory per platform                         | Per-actor calls with private memory are done (P0); a shared per-platform memory object and long-term memory consolidation are not                        | Keep the per-actor mode bounded by the call budget; consider a cheaper batched mode as an option                  |
| **Uncertainty**: multi-seed ensembles, intervals, sensitivity sweeps                  | A single deterministic trajectory over-states precision                                                                                                  | Surface bands in the trajectory and comparison charts                                                             |
| **Token and cost accounting with budgets and quotas**                                 | Usage is counted, but nothing estimates or caps spend                                                                                                    | Pre-run estimate, per-scenario hard cap, per-day cap                                                              |
| **Report grounding evaluation** against a labelled corpus                             | The verifier exists (P0) but its accuracy is unmeasured; only listed statements are checked                                                              | Build a labelled set of supported/unsupported/contradicted statements; measure precision and recall of each layer |
| **Graph evolution between rounds**                                                    | The source graph is static; only memory overlays evolve                                                                                                  | Evolve relationship strengths from recorded interactions; keep the source graph immutable                         |
| Semantic retrieval with a local vector store and a retrieval evaluation set           | Retrieval is lexical (sparse vectors) today                                                                                                              | Only where it measurably improves evidence selection                                                              |
| Append-only **audit log** and a retention/deletion policy                             | Per-project events exist; there is no cross-project, tamper-evident trail                                                                                | Hash-chained local log first                                                                                      |
| Storybook and design-system documentation                                             | Component states are not catalogued                                                                                                                      | Stories double as visual-regression fixtures                                                                      |
| Load and performance budgets in CI                                                    | A first local measurement exists (`scripts/load-test.mjs`); nothing gates regressions                                                                    | Turn the measured p95s into budgets; add a soak run; test with 100 stored projects of maximum size                |
| Manual assistive-technology pass (Narrator/NVDA, 200% zoom, reduced motion)           | Automated axe cannot judge task completion                                                                                                               | Record findings in the audit log                                                                                  |
| Retry countdown from `Retry-After` on rate-limit and queue-full errors                | The message says "wait a minute" but offers no timer                                                                                                     | Disable the action with a visible countdown; the header is already returned by the API                            |
| Default graph density: the simulated-memory overlay draws up to 48 diamonds           | The simulation stage graph is busy at first sight                                                                                                        | Default the overlay to the latest round only, or collapse by round                                                |
| Responsible-AI review and a prompt-injection red-team corpus run against a live model | Defences are structural; one live probe (obeyed in 24 of 24 statements before hardening, 0 of 144 after) and a heuristic echo guard exist, but no corpus | Pairs with the live-verification item above                                                                       |

## P2 — production-grade architecture

| Item                                                                                                                                          | Notes                                                                                                                                                                                                                                                                                       |
| --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Move simulation off the API event loop** (worker thread or separate process)                                                                | Measured: reads degrade to p95 ≈ 570 ms and max ≈ 1.8 s while simulations run, because rounds, JSON encoding and synchronous SQLite writes share the loop                                                                                                                                   |
| **Summary columns for the project list**                                                                                                      | `GET /api/projects` decodes every stored payload; its cost grows with the total size of stored runs, which the 100-project cap only bounds                                                                                                                                                  |
| **PostgreSQL** persistence with migrations (and pgvector if P1 retrieval proves out)                                                          | The `Repository` class is the single storage seam; keep the JSON-payload shape or normalise deliberately                                                                                                                                                                                    |
| **Durable jobs**: a separate worker, leased queue items, heartbeats, idempotent steps                                                         | Checkpoints already make steps resumable; the queue is currently in-process                                                                                                                                                                                                                 |
| **Entra ID** sign-in, **tenant isolation** (row-level security), **RBAC** roles, per-tenant quotas                                            | None of this exists; the local build is single-user with no authentication                                                                                                                                                                                                                  |
| Azure hosting: Container Apps (API and worker), Key Vault, managed identity to Azure OpenAI and PostgreSQL, Blob storage for source documents | Choose services only where they remove a real constraint; see [AZURE.md](./AZURE.md)                                                                                                                                                                                                        |
| **Bicep** for hosting, database, Key Vault and telemetry, and OIDC-based GitHub deployment                                                    | An Entra-only AI account + deployment template exists (`infra/`, built, linted and deployed once to a development subscription); hosting, database and telemetry templates do not                                                                                                           |
| **OpenTelemetry** traces, metrics and logs exported to **Application Insights**                                                               | Logging is structured and redacted, but there is no OTel instrumentation                                                                                                                                                                                                                    |
| **Microsoft Agent Framework** evaluation                                                                                                      | Its first-class SDKs are .NET and Python (confirm current status before deciding). Adopting it means a sidecar service or a re-platform, or keeping the TypeScript orchestrator and calling Foundry over REST. This is an architecture decision for the owner, not something to do silently |
| Supply chain: SBOM, provenance, Dependabot policy, signed images                                                                              | CI already runs `npm audit` and builds from a clean install                                                                                                                                                                                                                                 |
| Compliance review: data residency, retention, subject-deletion, pen test                                                                      |                                                                                                                                                                                                                                                                                             |

## P3 — research and product opportunities

- Backtest simulations against historical cases to learn where they are, and are not, informative.
- Larger populations (hundreds or thousands) through hierarchical or aggregate actors and batched inference.
- A temporal knowledge graph with evolving edges and GraphRAG over time.
- An experiment designer that proposes controlled branches and parameter sweeps automatically.
- Collaboration: shared workspaces, comments, approvals.
- Teams and Copilot surfaces, Power BI export, Foundry evaluations.
- Localisation.

## Recommendation after connecting Azure AI

Azure AI is connected (development subscription, Entra only, one `gpt-4.1-mini` deployment) and the P0
live-verification item is closed. Next, in this order:

1. **Replace the Legacy model.** `gpt-4.1-mini` retires on 2027-04-14. Request `gpt-5.4-mini` quota (or another
   current model with quota), re-run `npm run azure:provision` and `npm run azure:verify`, and compare the grounding
   counts with the table in [AZURE.md](./AZURE.md#live-evidence).
2. **Improve what the model writes, not only what is checked.** About 28% of the live report statements were not
   supported by the sources, and the analyst chat cited nothing in three of three runs. Tighten the chapter prompt,
   make the analyst chat cite, and build the labelled grounding-evaluation corpus (P1) before tuning further.
3. **Scale the live scenario** to the 10 proxies × 10 rounds maximum (about 200 actor calls) and watch the call
   budget, rate limits and cost.
4. **Red-team more widely** (P1): several injection phrasings, injection aimed at the grounding checker, and other
   models. The echo guard has never fired live, so it is not yet evidence of anything beyond its unit tests.
5. Keep the model deployment in the development subscription, authenticating with Entra ID (no key), and hold
   Container Apps, PostgreSQL, Key Vault, Entra sign-in and Application Insights until the P1 decisions (tenancy
   model) are made, because they shape the data model and the identity boundary.
