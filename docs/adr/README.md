# Architecture decision records

Short records of decisions that shape Swarm and that a reviewer should be able to challenge. Each
states what was decided, what it costs, and what evidence exists. A record marked **Proposed** has
not been built.

| Record                                                                        | Status            | Decision                                                                                                                                                                                                                |
| ----------------------------------------------------------------------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [0001](./0001-evidence-integrity-model.md)                                    | Accepted          | Every statement carries a type and a support class; a deterministic policy decides publication                                                                                                                          |
| [0002](./0002-abstention-and-citation-rule.md)                                | Accepted          | The analyst declines, without a model call, when the project's evidence cannot answer                                                                                                                                   |
| [0003](./0003-schema-migrations-and-audit-log.md)                             | Accepted          | Versioned migrations with a backup, and an append-only hash-chained audit log                                                                                                                                           |
| [0004](./0004-evaluation-approach.md)                                         | Accepted          | Hash-pinned labelled datasets, a dev/test split and floors, not targets                                                                                                                                                 |
| [0005](./0005-identity-roles-and-tenancy.md)                                  | Accepted          | Entra bearer tokens verified in the API, four roles, a default-deny route table, tenant scoping                                                                                                                         |
| [0006](./0006-postgres-adapter-proposed.md)                                   | Partly superseded | A repository interface and a PostgreSQL implementation for multi-user hosting; see 0009                                                                                                                                 |
| [0007](./0007-workspace-and-project-membership.md)                            | Accepted          | Workspace and project membership, seven roles; supersedes the role model of 0005                                                                                                                                        |
| [0008](./0008-browser-sign-in.md)                                             | Accepted          | Browser sign-in run by the server: Authorization Code with PKCE, a server-side session                                                                                                                                  |
| [0009](./0009-postgres-through-a-synchronous-bridge.md)                       | Accepted          | PostgreSQL behind the unchanged synchronous stores, through a worker-thread bridge; serializable, retried transactions                                                                                                  |
| [0010](./0010-durable-jobs-leased-from-the-database.md)                       | Accepted          | Stage jobs in the database, taken by a lease and a heartbeat, fenced writes, bounded retries, resumable simulations                                                                                                     |
| [0011](./0011-report-studio.md)                                               | Accepted          | A person works on a copy of the generated report: versions, locks, review and approval of exact text, regenerated chapters as proposals, a printable memo                                                               |
| [0012](./0012-answers-and-disputed-sources.md)                                | Accepted          | An answer says when a source it cites is disputed by another: a figure stated from one side is marked, and a conflict about the question is named                                                                       |
| [0013](./0013-per-project-model-budget.md)                                    | Accepted          | A project has a model budget (calls and tokens) held before every model call; only a workspace owner or administrator changes it                                                                                        |
| [0014](./0014-scenario-lab.md)                                                | Accepted          | One engine for any what-if question: project artifacts, stakeholders as a lens, repeated seeded runs with stated repeatability, critics that never edit                                                                 |
| [0015](./0015-premium-interface.md)                                           | Accepted          | The interface is scenes on a design system: the journey is the structure, tokens and a fixed cascade hold the look, the engine and its contracts stay                                                                   |
| [0016](./0016-research-and-constraints-are-artifacts.md)                      | Accepted          | Research runs, constraints and their counterfactual views are project artifacts, with no table and no migration                                                                                                         |
| [0017](./0017-research-is-the-first-phase-of-the-knowledge-job.md)            | Accepted          | Research is the first phase of the `knowledge` job: no new job kind, a run written whole, a bounded pause, a cut-off run starts again                                                                                   |
| [0018](./0018-fetching-is-deterministic-code-and-ai-is-advisory.md)           | Accepted          | Code decides what is fetched, through the one guarded fetcher; a model plans and ranks and never supplies an address; hostile text is labelled and never obeyed                                                         |
| [0019](./0019-one-output-policy-for-model-replies.md)                         | Accepted          | A model's reply is a strict schema, the server's checks and one correction, then the rules' answer, with a reason that holds none of the model's words                                                                  |
| [0020](./0020-the-foundry-provider-on-the-v1-api.md)                          | Accepted          | A Foundry provider on the v1 API: roles, not models; strict outputs; a router, allowances and a cache; proved against a fake and never run live                                                                         |
| [0021](./0021-the-deployment-guard.md)                                        | Accepted          | `DEPLOYMENT_MODE`: a pilot or production process refuses to start with an unsafe configuration; local is unchanged                                                                                                      |
| [0022](./0022-constraints-applied-or-read-and-hardness-a-proposal.md)         | Accepted          | A constraint is applied by the engine or only read; hardness is a proposal with a basis; a gate in rules; recall is below its threshold                                                                                 |
| [0023](./0023-the-decision-canvas-is-derived.md)                              | Accepted          | The Decision Canvas is derived on read: six statuses by ordered rules, four named lenses, no objective function, eight epistemic labels, no model                                                                       |
| [0024](./0024-a-deterministic-scope-check-says-what-swarm-does-not-decide.md) | Accepted          | A deterministic reading of the question's words puts a notice on a matter of employment, credit, legal, medical or safety, and makes a decision about one person a human decision; it is incomplete and refuses nothing |

Records 0016 to 0024 are the decisions of the production-v1 wave. Each says what has been run and what has not:
none of them has met Azure.

New records take the next number and never rewrite an accepted one; a reversed decision gets a new
record that says so.
