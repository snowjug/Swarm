# Security review — Swarm Lab

Date of review: 27 Oct 2026. Scope: the repository at the commit that contains this file, running as
a local single-user application. This is an evidence log, not an assurance claim: **the application is
not claimed to be secure.** Each section says what was run, what it showed, and what remains.

See [threat-model.md](./threat-model.md) for the full threat table and residual risks.

## What the automated tests actually prove

- **Prompt-injection boundary** (`security.test.ts`): with a hostile source document and question, every
  setup call and every per-proxy simulation call carried the hostile text **only** in the untrusted `data`
  argument and **never** in the trusted `instructions`. The wire format
  (`client.test.ts`) places `data` under an `untrustedScenarioData` key behind a system boundary that
  states the model has no tools.
- **Hostile provider output** (`security.test.ts`, `actor.test.ts`): invented citations (`S999`), a graph
  node whose quote is not verbatim in its cited passage, per-proxy decisions that name a peer the proxy
  never saw, a reply that names nobody, a source it does not hold, an out-of-range opinion, an opinion
  jump beyond the per-round limit, or an empty statement are each rejected with `MODEL_OUTPUT_INVALID`
  (after at most two corrective retries when a real client is used); the stage ends `failed`, nothing is
  persisted as complete, and the model's own fabricated text is not echoed into the persisted error.
- **Per-proxy isolation** (`actor.test.ts`): the data sent for one proxy contains its own profile and
  private memory but never another proxy's persona, goals, memory, rationale or confidence, and never the
  other platform's data. Silence ("observe") is invisible to peers.
- **Grounding cannot be talked into support** (`grounding-verify.test.ts`, `grounding-review.test.ts`):
  an independent model judgement can lower or confirm a verdict but never create `supported` without word
  overlap with the cited passage, and every positive or negative judgement must quote real text from it.
  This limits, but does not eliminate, what an injection inside a passage can do (see finding 12).
- **Entra token hygiene** (`entra.test.ts`): the bearer token is sent only to an allow-listed Azure AI
  host, never in a URL, log, error, status response or persisted state; a credential failure yields a
  generic `MODEL_AUTH` message that does not include account, tenant or token details.
- **Provider error handling** (`client.test.ts`): a 400 from the provider is classified from its machine
  codes only (content filter, unsupported parameter, context window), never from its message; hostile
  parameter or code names, oversized bodies and non-JSON bodies yield the generic error; a content-filter
  block is `MODEL_REFUSED` with no fallback.
- **Provisioning safety** (`scripts/azure/lib/*.test.ts`): with a fake Azure CLI, nothing is deployed
  without `--yes`, a production-looking or disabled subscription is refused before any permission check,
  a read-only account is stopped with the missing permissions named, a foreign resource group is refused,
  teardown deletes only resources tagged `app=swarm-lab`, `.env` accepts only four allow-listed non-secret
  settings with strict value patterns, and Azure CLI output is scrubbed of tokens and secret fields.
- **Log hygiene** (`security.test.ts`): with a provider that returns 401 containing the API key and a
  marker, debug logs, the project JSON and the JSON export contain none of: the key, the provider body,
  the source-text marker, a query-string secret, or an `Authorization` header value.
- **Browser boundary** (`security.test.ts`, `app.test.ts`): foreign Origins and spoofed Host headers are
  refused (including preflights); no permissive CORS header is ever emitted; non-JSON bodies are
  rejected; provider requests use `redirect: 'error'`.
- **Input handling** (`contracts.test.ts`, `pdf.test.ts`): traversal-style and control-character
  filenames, binary content, oversize and corrupt PDFs are rejected before use.
- **Integrity** (`whatif.test.ts`): checkpoints are accepted only when the history and every platform
  agree; tampered checkpoints are refused; branches never modify their parent.
- **Rate limiting** (`security.test.ts`): the 21st request in a minute to a 20-per-minute route returns
  HTTP 429 `RATE_LIMITED` with a request ID and `Retry-After`; the new `RATE_LIMIT_SCALE` setting is
  validated (integer 1–1000) and defaults to 1. **This test found a real defect:** the limiter previously
  answered HTTP 500 `INTERNAL_ERROR`, so users never saw the intended message and the server logged
  false errors. Fixed in `backend/src/app.ts`.
- **Hostile HTTP in a real browser stack** (`e2e/local/errors.spec.ts`): foreign Origin → 403
  `ORIGIN_NOT_ALLOWED`; a 700 KB body → 413; a `text/plain` body → 4xx and nothing created.

## Not covered by this review

Penetration testing, fuzzing of the PDF parser, sustained (soak) and distributed load/DoS testing,
review of provider-side data handling, and any behavior of a live model. One local load run exists
(`scripts/load-test.mjs`); it is a measurement for one machine, not a capacity guarantee. These gaps
are listed in the roadmap.
