# Threat model — Swarm Lab (local single-user build)

Status: written against the code and tests in this repository. It is an engineering threat model,
not a certification. Nothing here claims the application is "secure"; each row states what is
mitigated, how that is evidenced, and what residual risk remains.

## Scope and assumptions

- One operator, one machine, loopback only (`HOST=127.0.0.1` by default). By default (`AUTH_MODE=none`)
  there is **no authentication or multi-user separation**; any process running as the same OS user
  can reach the API. Exposing the port to a network in that mode is explicitly unsupported. A
  signed-in mode with roles and tenant isolation exists (`AUTH_MODE=entra`); its threats are in the
  [addendum](#addendum-evidence-ledger-sign-in-and-tenancy) below, and it has not been used with a
  real tenant.
- All scenario content is user-supplied and treated as **untrusted data**: documents, questions,
  persona text, seed posts, provider output.
- Model providers (Azure OpenAI, OpenAI-compatible, Ollama) are optional and operator-configured via
  environment variables. The default mode is a deterministic local engine that makes no network call.
- Not in scope for this build: cloud hosting. The API can verify Microsoft Entra bearer tokens and
  sign a person in through the browser (server-side session; see the addendum and
  [ADR 0008](./adr/0008-browser-sign-in.md)), enforce roles and separate tenants, but none of that has
  met a real tenant. Model-side Entra ID authentication and a user/managed identity for calling
  Azure AI **are** in scope and were exercised live with a user identity. Remaining gaps are tracked
  in [microsoft-product-roadmap.md](./microsoft-product-roadmap.md).

## Assets

| Asset                          | Where                                                     | Why it matters                                       |
| ------------------------------ | --------------------------------------------------------- | ---------------------------------------------------- |
| Source documents and scenarios | SQLite file under `DATA_DIR`                              | User-confidential content                            |
| Provider API key (legacy mode) | Process environment only                                  | Spend and data-exfiltration capability               |
| Entra access token (default)   | Process memory only, cached by `@azure/identity`          | Short-lived capability to call the model as the user |
| Azure CLI login                | The operator's own `az` token cache, outside this project | Control of the operator's subscriptions              |
| Run history and checkpoints    | SQLite (`console` payload)                                | Integrity of results and what-if lineage             |
| Exports                        | Generated on request (Markdown/JSON)                      | Leaves the system; must not leak secrets             |

## Trust boundaries and data flow

```
Browser (React) ──HTTP, loopback──▶ Fastify API ──▶ SQLite (node:sqlite, parameterized)
                                        │
                                        ├──▶ PDF worker thread (resource-limited, no env/credentials)
                                        ├──▶ Orchestrator queue ─▶ Local engine (pure functions)
                                        └──▶ ModelGateway ──HTTPS──▶ Provider (optional)
```

Boundaries: (1) browser/any local process → API; (2) uploaded bytes → PDF parser; (3) untrusted text →
model prompt; (4) model output → persisted state; (5) server → provider.

## Unsafe tool access (explicit)

The model receives **no tools, shell, filesystem or web access**. `ModelGateway.json()` is the only
model interface: it returns schema-validated JSON. Evidence retrieval, memory search and interviews
are server-side functions called by deterministic orchestration code. A model can at most _name_ a
retrieval query that the server then runs read-only over the same project's own passages.
Each per-proxy call additionally receives only that proxy's own bounded context, and its reply may
only reference peers and passages that were in that context.

## Review cadence

Re-run `npm audit`, `npm run scan:secrets` and the security tests (`backend/test/security.test.ts`) before
every release, and revisit this model when adding authentication, hosting, new providers, or any tool
that can act outside the project's own data.
